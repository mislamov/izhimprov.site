# CRM ICS calendar
Cloudflare Free Worker reads only the scoped CRM calendar.events contract. No Alfa client or credentials.
Set PRIMARY_CRM_URL in wrangler.toml and PRIMARY_CRM_CALENDAR_TOKEN using wrangler secret put. Keep existing CALENDAR_SECRET for subscriber URLs. CRM needs a distinct CRM_INTEGRATION_CALENDAR_TOKEN and explicit public type/pair allowlists. Deny-all by default; never use read/write integration token for this Worker.
GET /calendar/crm.ics?token=... and the compatible /calendar/alfacrm.ics?token=... use the same new CRM cache namespace. GET /health returns sync status; authenticated /admin/run-sync refreshes. Hourly cron unchanged. Do not paste private subscription URLs in reports.
Whitelist removes notes, participants, contacts and staff. Stable imported UID preserved; local UID has a separate namespace. Europe/Samara, version/SEQUENCE and STATUS:CANCELLED are supported. Incomplete or failed reads leave last successful ICS intact; old Alfa cache is never served.
Validation: npm ci --ignore-scripts; npm test (9 tests). Actual HTTP acceptance is ops.consumer_acceptance in improv-crm; it uses synthetic data, restricts network to test CRM and checks UID/TZ/privacy. Full runbook: improv-crm/docs/CONSUMERS_CRM_133.md.
